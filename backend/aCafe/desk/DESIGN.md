# desk 設計: テーブルとチャット空間

店内は「テーブルを繋げた1つの大きな空間」。テーブルは話題ごとに作られ、**人数の上限は無い**。
誰かが座るとそのテーブルのチャット空間(`Room`)に合流する。一人で座っているとキャラクターAIが入ってくる。

## 体験の流れ

1. **店内を見る** `GET /api/desk/tables/`
   - テーブルごとに話題(name)、「誰かいます/誰もいません」、人数、同席しているキャラ、雰囲気ひとことを返す。
   - `floor.human_count` に店内全体の人数が入る。
   - 雰囲気ひとこと = オーナーAI(`generate_room_atmosphere_summary`)が直近の会話から作る1〜2文。会話内容は伝えず、空気感だけ伝える。
2. **座る** `POST /api/desk/tables/<id>/sit/` body: `{"anon_id": "..."}`
   - 誰かいれば同じ `Room` に合流(何人でも)。誰もいなければ新しい `Room` を作る。
3. **話題でテーブルを作る** `POST /api/desk/tables/` body: `{"anon_id": "...", "name": "最近読んだ本"}`
   - テーブルと `Room` を作り、そのまま座る。話題は1〜30文字(`400`)、テーブル数の上限は `DESK_MAX_TABLES`(既定50, `409`)。
4. **話す** WebSocket(`ws_path`)上で `chat.message` を送受信。キャラが参加していれば返事をする。
5. **テーブルを離れる** WebSocket を閉じる。最後の1人が離れたらキャラは解放される。

レスポンスの `table` / `room_id` / `ws_path` / `user` は、座る・作るで共通。

## テーブルの種類

| 種類 | 作る人 | 全員が離れたとき |
|---|---|---|
| 常設(`is_permanent`) | 初期データ(マイグレーション): ゆるく雑談 / 今日あったこと / おすすめの本・音楽・食べもの / ひとりごと | 残る。次に座る人には新しい `Room` を作る |
| 利用者が作ったもの | 話題を付けた利用者 | 閉じる(`close_empty_tables`)。`Room` と発言ログはDBに残す |

テーブルの状態は2つだけ。

| 状態 | 条件 |
|---|---|
| vacant(誰もいません) | 在席が0人で、座った直後の予約(`DESK_SIT_GRACE_SECONDS`, 既定30秒)も無い |
| occupied(誰かいます) | 在席が1人以上、または座った直後で予約内(座る〜WebSocket接続の隙間で消えないようにする) |

## しばらく一人でいるとキャラが入ってくる

- 接続時に人間が自分1人だけ、かつキャラがいなければ、30〜60秒(`DESK_LONELY_JOIN_SECONDS`)後に入室をスケジュールする。
- 待ち時間が過ぎた時点でまだ一人きりのときだけ、`pick_characters_for_room` で選んだキャラ1人が入室し、あいさつを1発言する。
  誰かが同じテーブルに来ていたり、離れていたら何もしない。
- キャラは同時に複数のテーブル/部屋にいない(既存の排他ルール)。
- `simulate_ambient_life`(無人部屋のキャラ補充・雑談)はテーブルの部屋を対象にしない。座った人が最初からキャラのいるテーブルに着いてしまうと、この演出が成り立たないため。

## 在席の数え方(Presence)

カウンタの増減ではなく、接続ごとの `Presence`(最終確認時刻つき)を数える。

- 入室で作成、クライアントが15秒ごとに `{"type":"ping"}` を送って更新、退室で削除。
- `DESK_PRESENCE_TTL_SECONDS`(既定120秒)更新が無い行は在席に数えない。サーバーやconsumerが異常終了して
  `disconnect` が呼ばれなくても、時間が経てば自動で外れる(幽霊でテーブルが埋まったままにならない)。
- 期限切れの行は一覧の取得・座る操作のたびに掃除し、無人になった部屋のキャラを解放する。
- 最後の1人が離れたら、座った直後の予約(`sat_at`)も解除する。離れた直後に「誰かいます」と出ない。

## Redis のタイムアウト

redis-py 8系は `socket_timeout` の既定が5秒になった。channels_redis の待ち受け(`bzpopmin`, 5秒)と同じ長さなので、
誰も発言しない間に `Timeout reading from redis` でconsumerが落ち、接続が切れる。
`CHANNEL_LAYERS` の hosts で `socket_timeout: 30` を明示して回避している。

## 雰囲気ひとことの生成ルール

- 発言がまだ無いテーブル: 固定文「座ったばかりで、まだ静かなテーブルです。」(AIを呼ばない)。
- 前回の生成後に新しい発言があり、かつ最短間隔(`DESK_ATMOSPHERE_MIN_SECONDS`, 既定60秒)が過ぎていれば作り直す。
- Ollama が落ちていても一覧は返す(タイムアウト `DESK_ATMOSPHERE_TIMEOUT` 既定8秒、失敗時は古い文を使い、更新時刻は進めて連続待ちを避ける)。

## ファイル

- `models.py`: `Table`、`Presence`(在席)、`Room`、`Message`
- `tables.py`: テーブルの作成・座る・状態・在席の管理・片付け・雰囲気ひとこと
- `views.py` / `urls.py`: テーブルAPI
- `consumers.py`: WebSocket(一人のときのキャラ入室、AI失敗時も接続を保つ、ping)
- `migrations/0007_seat_to_table.py`: 定員つきの座席をテーブルに置き換え、常設テーブルを投入
- フロント: `frontend/acafesomewhere/app/desk/`

## 今後の課題

- 人数が増えたときのキャラの返信量(今は参加キャラ全員が毎発言に返す)。
- 話題の重複・不適切な話題名への対応。
- `anon_id` は自己申告のまま(なりすまし対策は未対応)。
- 在席は接続数なので、同じ人が複数タブで開くと複数人として数える。
- 一覧はポーリング(10秒)。変化をプッシュしたければ専用グループを追加する。
